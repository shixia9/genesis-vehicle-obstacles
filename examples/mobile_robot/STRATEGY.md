# `room_navigation.py` 策略说明

本文档说明 `room_navigation.py` 当前实际使用的导航与避障方法。本文件描述的是 MVP 版本，不代表后续动态 URDF 车辆或强化学习策略的最终方案。

## 1. 策略概览

本案例采用：

> 固定航点跟踪（waypoint following）+ LiDAR 前向安全层（reactive safety layer）

整体控制链路如下：

```text
房间与障碍物场景
        ↓
LiDAR / 深度相机 / IMU
        ↓
LiDAR 数据清洗
        ↓
前方障碍物检查
   ┌────┴────┐
有近障碍物       无近障碍物
   ↓                 ↓
停车并原地转向    航点跟踪控制
   └────┬───────────┘
        ↓
差速运动学更新车体位姿
        ↓
推进 Genesis 场景、记录 telemetry、检查碰撞
```

车体和车轮目前是固定的 Genesis 几何体，车体位姿由差速运动学直接更新；当前版本不是通过动力学接触和轮胎摩擦来驱动车辆。

## 2. 场景、车辆与传感器

### 2.1 车辆模型

- 初始位置：`(-2.8, -1.8, 0.22)`。
- 初始航向：`yaw = 0`。
- 车体尺寸：约 `0.72 × 0.50 × 0.20 m`。
- 碰撞近似使用车体半长 `0.36 m`、半宽 `0.25 m`。
- 线速度上限 `0.75 m/s`，角速度上限 `1.5 rad/s`。

### 2.2 LiDAR

LiDAR 是当前唯一直接参与避障决策的传感器：

- 72 条射线，覆盖 `[-180°, 180°)`；
- 安装在车体中心前方约 `0.60 m`；
- 最大测距 `6.0 m`；
- 无效、非有限或非正距离被替换为 `6.0 m`；
- 前方安全阈值为 `0.55 m`。

`0.55 m` 的阈值同时考虑了 LiDAR 相对车体的位置和车体自身长度，用于保留安全余量并减少房间边界造成的误触发。

### 2.3 深度相机与 IMU

深度相机和 IMU 会被创建、读取并写入 telemetry，但目前不参与控制决策：

- 深度相机：提供车载前向传感器输出；
- IMU：记录线加速度和角速度范数；
- 避障判断只使用 LiDAR。

## 3. 航点路线

控制器按顺序跟踪以下航点：

```text
航点 0: (-2.8, -2.1)
航点 1: (-2.8,  1.7)
航点 2: ( 2.8,  1.7)
```

车辆到当前航点的距离小于 `0.28 m` 时切换到下一个航点。到达最后一个航点且距离小于 `0.28 m` 时，控制器返回 `reached=True`，并输出零线速度和零角速度。

这条路线是预先给定的，不会根据障碍物位置重新生成。

## 4. 避障策略

避障逻辑位于 `DifferentialDriveController.command()`，优先级高于航点跟踪。

### 4.1 前方障碍物判定

控制器取 LiDAR 前方 `±32°` 扇区中的最小距离。当满足以下条件时，认为前方存在近距离障碍物：

```text
min(front_lidar) < 0.55 m
```

该判断不区分障碍物、墙体或其他几何体；任何前方近距离回波都会触发安全层。

### 4.2 选择转向方向

触发安全层后，车辆立即停止前进：

```text
线速度 v = 0
```

然后比较左右两侧的平均 LiDAR 距离：

- 左侧扇区：`20° ~ 115°`；
- 右侧扇区：`-20° ~ -115°`。

转向规则为：

```text
左侧平均距离 >= 右侧平均距离：w = +1.5 rad/s
否则：                         w = -1.5 rad/s
```

车辆会朝平均空闲空间更大的一侧原地旋转，直到前方 `±32°` 范围内的最小距离恢复到 `0.55 m` 以上。随后重新回到当前航点跟踪。

### 4.3 策略性质

这是一个局部、反应式的“停车—选空旷侧—原地旋转”策略：

- 不建立栅格地图或障碍物地图；
- 不预测障碍物运动；
- 不计算绕障碍物的全局路径；
- 不修改原有航点；
- 避障结束后继续追踪原来的当前航点。

## 5. 无障碍时的航点控制

当安全层未触发时，控制器对当前航点进行比例式航向控制。

设当前位置为 `p`，当前航点为 `g`，当前航向为 `yaw`：

```text
relative_target = g - p
distance = ||relative_target||
target_heading = atan2(relative_target_y, relative_target_x)
heading_error = wrap(target_heading - yaw)
```

线速度和角速度计算为：

```text
v = min(0.75, 0.9 × distance)
v = v × max(0, cos(heading_error))

如果 |heading_error| > 0.5 rad：
    v = 0

w = clip(2.0 × heading_error, -1.5, +1.5)
```

因此，离航点越远时速度越大但不超过 `0.75 m/s`；航向偏差较大时先原地转向，航向基本对准后才向前行驶。

## 6. 每个仿真步的执行顺序

主循环中的顺序如下：

1. 读取里程计估计的位置和航向；
2. 读取 LiDAR 距离并清洗数据；
3. 调用 `controller.command()` 计算线速度和角速度；
4. 用差速运动学更新车体和车轮位姿；
5. 积分更新控制器使用的里程计；
6. 调用 `scene.step()` 推进 Genesis 场景；
7. 读取传感器并记录 telemetry；
8. 执行近似碰撞检查；
9. 到达目标或发生碰撞时提前结束。

正式控制循环前会先执行一次 `scene.step()`，用于填充传感器缓存，避免初始零值 LiDAR 数据被误判为障碍物。

## 7. 碰撞检查与避障的区别

`geometry_collision()` 只是结果判定器，不是避障控制器。它根据车体近似尺寸检查：

- 是否越过房间边界；
- 是否与固定障碍物的二维投影重叠。

它不会生成控制指令。即使 LiDAR 安全层没有触发，几何检查仍可能将车辆标记为碰撞；反过来，触发 LiDAR 安全层也不代表已经发生碰撞。

## 8. 已知局限与后续扩展方向

当前策略适合验证“场景—传感器—控制器—运动—日志”的闭环，但不适合作为通用移动机器人导航器：

- 只检查前方，侧后方障碍物不会直接触发安全层；
- 使用左右平均距离，可能忽略窄通道、局部缺口或障碍物形状；
- 原地转向后仍追踪原航点，可能在凹形障碍物前反复转向；
- 没有速度相关的动态安全距离；
- 没有动态障碍物预测和避让；
- 里程计是对控制命令的积分，不是融合真实车辆运动和传感器的定位结果；
- 当前车辆没有动态接触、轮胎摩擦或真实轮速执行器模型。

后续若升级策略，建议保持当前 `command(position, yaw, lidar_distances)` 的观测—动作接口不变，并考虑：

1. 使用障碍物历史和局部代价地图；
2. 将“原地转向”升级为局部轨迹采样或 DWA 类控制；
3. 增加速度相关的安全距离和减速曲线；
4. 接入真实轮速、动力学接触和更可靠的定位；
5. 在接口稳定后替换为学习策略或全局规划器。

## 9. 运行验证

CPU 短测试：

```bash
python examples/mobile_robot/room_navigation.py --steps 300
```

完整 CPU 回归：

```bash
python examples/mobile_robot/room_navigation.py --steps 1200
```

在固定种子和默认场景下，完整 CPU 回归通常在约 783 步到达目标，并且不发生几何碰撞。
